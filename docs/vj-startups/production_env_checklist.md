# Production Environment Variable Checklist

Everything below was verified against the actual local `.env` files and the settings/code
that reads each variable on 2026-09-21. "Local value" is what's currently sitting in the
gitignored local `.env` (never commit these); "Production" says exactly what has to
replace it and where that value comes from.

## 3. Frontend apps (`apps/web/.env`, `apps/admin/.env`, `apps/space/.env`, `apps/live/.env`) — build-time `VITE_*` vars

All of these are just the production versions of the same URLs configured above. Set them to the real domains, not localhost:

- `VITE_API_BASE_URL` → `https://plane.vjstartup.com` (or wherever the API is reachable from the browser)
- `VITE_WEB_BASE_URL`, `VITE_ADMIN_BASE_URL`, `VITE_SPACE_BASE_URL`, `VITE_LIVE_BASE_URL` (+ their `_PATH` counterparts) → matching production domains
- `apps/admin/.env`'s `VITE_ENABLE_*` feature flags (`VJ_STARTUPS`, `PUBLIC_SHOWCASE`, `REPUTATION_SYSTEM`, `STARTUP_FUNNEL`) → keep `=1` to ship what's been built this session
- `apps/live/.env`'s `LIVE_SERVER_SECRET_KEY` → must match `apps/api/.env`'s value (see above)

These are baked in at **build time** (Vite), not read at runtime — the production build pipeline needs these set before `pnpm build` runs, not just on the server afterward.

## 4. Things that are correct as-is and need no production override

- `FILE_SIZE_LIMIT`, `SIGNED_URL_EXPIRATION` — sane defaults, no action needed.
- `DOCKERIZED`, `GPT_ENGINE`, `OPENAI_API_*` in the root `.env` — marked `# deprecated` in the file itself, leave alone.
- `RABBITMQ_*` in the root `.env` — only relevant if the docker-compose deployment path is used; Plane's Celery config runs fine on Redis alone via `apps/api/.env`'s `CELERY_TASK_ALWAYS_EAGER` (dev-only) — confirm which broker the chosen production deployment method (Docker vs bare VPS) actually needs before carrying this over.

## 5. Cross-checks before going live

1. `PUBLIC_SITE_INTERNAL_TOKEN` (Plane) == `PLANE_INTERNAL_TOKEN` (backend 2) — byte-for-byte.
2. `LIVE_SERVER_SECRET_KEY` — identical in `apps/api/.env` and `apps/live/.env`.
3. `VJ_MICROSERVICE_URL` (Plane) actually resolves to backend 2's real deployed address, and `PLANE_API_URL` (backend 2) actually resolves back to Plane's — check both directions, not just one.
4. `VJ_MICROSERVICE_ADMIN_TOKEN` belongs to a real admin who has actually logged into the **production** admin panel at least once (the token doesn't exist until then) — this can't be set before the first production login.
5. Two separate Google OAuth Client IDs exist (Plane's team login vs. backend 2's public-site login) with correct, separate authorized origins — verify in Google Cloud Console, not just in `.env`.
